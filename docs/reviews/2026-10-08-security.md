## Fix in code

### R1. `exec` does not replace a variable that is already set

Code: open. Docs: done, 2026-10-08, [README](../../README.md), [getting-started](../getting-started.md), [sshagent-cred](../sshagent-cred.md), [security.md](../security.md).

[cmd/sshagent-cred/main.go](../../cmd/sshagent-cred/main.go#L251) copies the process environment and appends `VAR=value`. On Linux and on macOS the first match wins. A shell that already has `TOKEN` set will hide the Credential, and the program will use the old value with no error.

Checked on 2026-10-08 with a throwaway program using `syscall.Exec` the same way. The child printed `from-parent`, not `from-credential`.

[TestExecInjectsCredential](../../cmd/sshagent-cred/main_test.go#L139) does not preset `TOKEN`, so it does not catch this.

Workaround until the code changes: `env -u TOKEN sshagent-cred exec -e TOKEN=name -- command`.

Fix: drop any existing entry for that name before appending. Add a test that presets the variable.

### R2. `encrypt` trusts `recipient.txt`

Code: open. Docs: done, 2026-10-08, [sshagent-cred](../sshagent-cred.md), [security.md](../security.md).

[recipient](../../internal/store/store.go#L292) reads `recipient.txt` and [Put](../../internal/store/store.go#L90) encrypts to it. Nothing compares that file with the identity payload, or with a public key re-derived from the agent. The `# public key:` comment in `identity.txt` is not a check either. Both files can be edited together.

Someone who can write the store, and cannot reach the agent, cannot decrypt old Credentials. They can replace `recipient.txt` with their own `age1...` key. The next `encrypt` needs no agent, no prompt, and no error. New secrets go to them. A sync conflict or a pulled commit does the same thing without anyone being malicious.

[Init](../../internal/store/store.go#L78) writes `identity.txt`, `recipient.txt`, and `export-check.age` from a map, so the order is random, and nothing locks the directory. A crash, or two `init` processes, can leave the identity and the recipient pointing at different keys.

Workaround: after every copy, sync, or pull, re-derive and compare. Do not compare the comment.

```sh
age-plugin-sshagent recipient -i identity.txt
```

Fix: when the agent is reachable, re-derive the recipient and refuse to encrypt on a mismatch. Comparing the comment to `recipient.txt` is not a fix. Do not drop `recipient.txt` without deciding that `encrypt` must start requiring the agent. That was the point of the separate file.

### R3. NUL bytes are accepted as text

Code: open. Docs: done, 2026-10-08, [sshagent-cred](../sshagent-cred.md), [security.md](../security.md).

[Put](../../internal/store/store.go#L106) rejects values that are not UTF-8. A NUL byte is valid UTF-8. `exec` then puts the value in the C environment, which ends the string at the first NUL. The program sees a truncated secret. `token` writes the full bytes, so the two commands disagree.

Fix: reject a NUL in `Put`. One test is enough.

### R4. Import does not roll back

Code: open. Docs: done, 2026-10-08, [sshagent-cred](../sshagent-cred.md), [security.md](../security.md).

A conflicting import writes nothing. That part holds, and the error lists names, not values. After that check, [the write loop](../../internal/store/store.go#L268) calls `Put` one Credential at a time. If a later write fails, the earlier ones are already replaced. `--overwrite` has no second confirmation. An old backup, or a file you did not export, becomes the store.

Fix if you touch this code: stage the new files and rename them into place. If you decide a partial import is fine, change this row from open to accepted and say why. Do not claim the current loop is atomic.

## Warn, and only change the code if it is cheap

### R5. `-k` and `SSH_AUTH_SOCK` are trusted at creation

Code: open. Not the first fix. An exact-match flag is still not implemented, so this is not accepted. Docs: done, 2026-10-08, [getting-started](../getting-started.md), [security.md](../security.md).

[PickKey](../../internal/derive/derive.go#L313) matches a substring of the comment or the fingerprint. Comments are chosen by whoever added the key. If the substring matches one key, that key is used, even when it is the wrong one. An ambiguous match is refused. A short unique match is not.

`keygen` and `init` use whatever agent `SSH_AUTH_SOCK` points at. A substituted socket binds the new identity to a key that agent can sign. Signature verification does not catch this. The agent is signing for a key it advertised.

The code already prints the fingerprint. The habit is to read it before encrypting anything to the new recipient. An exact-match flag would be nicer. It is not the bug to start with.

### R6. `age -e -i` asks the agent to sign

Code: accepted. This is how age turns an identity into a recipient. A code change that blocked `-i` on encrypt would surprise age users, and it would not stop a substituted plugin. Docs: done, 2026-10-08, [age-plugin-sshagent](../age-plugin-sshagent.md), [getting-started](../getting-started.md), [security.md](../security.md).

[HandleIdentityAsRecipient](../../cmd/age-plugin-sshagent/main.go#L49) derives the private key to recover the recipient. `age -e -r age1...` does not run the plugin. `age -e -i identity.txt` does, and it is the same capability as decryption.

### R7. `age` runs whatever `age-plugin-sshagent` is on `PATH`

Code: accepted. age looks plugins up by name. A local allowlist would be a different design, and it would not bind a binary the user put first on `PATH` on purpose. Docs: done, 2026-10-08, [age-plugin-sshagent](../age-plugin-sshagent.md), [getting-started](../getting-started.md), [security.md](../security.md).

A different binary with that name receives the identity stanza and can request signatures while it runs as you. Install the built plugin in a directory you control. Do not put `.` on `PATH`.

### R8. Directory mode, and the password error string

Code: open. Cheap, and still not done. Docs: done, 2026-10-08, [sshagent-cred](../sshagent-cred.md), [security.md](../security.md).

[writeFile](../../internal/store/store.go#L335) uses `os.CreateTemp`, which creates the file mode `0600`. That holds. `init` creates missing directories mode `0700` and does not tighten a directory that already exists. A `SSHAGENT_CRED_DIR` you created as `0755` leaks Credential names. `export-check.age` in a directory others can read is an offline guessing oracle.

The length check is [12 bytes](../../internal/store/store.go#L68). The error says characters. age's default scrypt cost is work factor 18, so N is 2^18, with r=8 and p=1. Nothing else checks the password.

Fix the error string, and `chmod` the store directory on `init`, when you are next in that file. Do not add a password-strength policy as a drive-by.

### R9. The export password does not stop exfiltration

Code: accepted. The password exists so an agent cannot pick its own export password. Making `token` ask for it would break the reason the store exists. Docs: done, 2026-10-08, [security.md](../security.md), [sshagent-cred](../sshagent-cred.md), [ADR 0004](../adr/0004-password-protected-exports.md).

`token` and `exec` need no password. A process that can run `sshagent-cred` can print every Credential. [ADR 0004](../adr/0004-password-protected-exports.md) is narrower than it reads. The password stops the `export` command from succeeding unattended. It does not stop `token`.

### R10. A parent can read the password prompt

Code: accepted. Another prompt does not stop a parent that started the process. Docs: done, 2026-10-08, [security.md](../security.md).

The terminal prompt is real for stdin, arguments, and the environment. It is not real against a parent that starts the process. On Linux, Yama `ptrace_scope` 1 lets a parent trace its child. That was the setting on the machine where this was reviewed. This review did not show that `LD_PRELOAD` steals the password. The packages have no cgo files, and the password read is a syscall, so a libc preload is the wrong bypass to claim. A wrapper earlier on `PATH`, or a debugger, is enough.

### R11. The confirmation prompt does not name the request

Code: accepted. Changing the challenge changes every derived key and needs a new payload version. Do not do that to make the prompt prettier. Docs: done, 2026-10-08, [security.md](../security.md).

The [challenge](../../internal/derive/derive.go#L173) is the fixed string `age-plugin-sshagent/v1/derive`, a NUL, then the salt. A prompt that shows the data as a C string shows that same prefix every time. A prompt still stops silent use. It does not tell you what you approved.

### R12. `keygen` signs twice. Decrypt does not

Code: accepted. A later mismatch fails decryption. It does not return someone else's plaintext. Repeating the check on every decrypt costs a signature and does not change that outcome. Docs: done, 2026-10-08, [security.md](../security.md).

`keygen` signs twice and refuses a mismatch. Decrypt does not repeat that check.

### R13. Memory is not wiped

Code: accepted. Go will not make a reliable wipe cheap. A best-effort zeroing patch must not be recorded as done. Docs: done, 2026-10-08, [security.md](../security.md).

Passwords, HKDF output, and Credential bytes are not wiped.

### R14. `token` writes the secret to stdout

Code: accepted. That is the interface. A mode that refused stdout would remove the reason `token` exists. Docs: done, 2026-10-08, [sshagent-cred](../sshagent-cred.md), [getting-started](../getting-started.md).

Command substitution into another program's arguments puts the secret in the process list. Prefer `exec`, and unset the variable first.

## What held

- The signature is checked against the public key before HKDF. A bad signature is an error, not a different key.
- RSA identities pin `rsa-sha2-512` or `rsa-sha2-256`. SHA-1 `ssh-rsa` is not used. A different format is an error, not a fallback.
- Ed25519 identities stay on payload version 1. The golden test is what pins that. This review did not re-derive it.
- Credential names cannot be `..` or an absolute path. The pattern requires each segment to start with a letter or a digit.
- Passwords are read from `/dev/tty` only, not from stdin, arguments, or the environment.
- `export` uses `O_EXCL` and mode `0600`, and refuses a file that already exists.
- A conflicting import lists names, not values, and writes nothing.
- `exec` does not go through a shell.
- A ciphertext cannot choose the identity. age sends the identities you passed with `-i`. Replacing `identity.txt` with a key the agent does not hold fails decryption.
